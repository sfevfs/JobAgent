# CodexJobAgent 2026-09-25 多候选人找岗更新（公开匿名版）

适用基线：`CodexJobAgent-Share-20260915`。此包是覆盖式程序更新，不是完整项目，也不导入本机的投递记录。

## 本次升级

1. **候选人隔离。** 找岗命令必须显式指定 `candidate_a` 或 `candidate_b`。不同候选人的事实、画像、资格配置、发现的岗位、报告和 SQLite 库分别存放；旧的 `.local/` 单人资料与 `data/runtime/discovered_jobs/` 保留原样。
2. **Candidate A 匹配器更新。** 新增独立的 `job_matcher_candidate_a.py` 和评分配置，包含更细的通信/CSI、医学影像/CV 方向识别、直接证据与可迁移能力的边界，以及技术匹配、资格、偏好分开输出。Candidate B 继续使用 9 月分享版的通用匹配器，避免 Candidate A 的专用项目规则影响 Candidate B 的分数。
3. **岗位发现与来源质量。** 去重后保留“岗位名称搜索”和“产品场景搜索”的发现来源、公司产品证据、企业规模；待复核清单标记来源日期、JD 完整度和产品证据缺口。公司规模只影响查找顺序，不决定岗位是否合格。
4. **产品反推企业。** Candidate A 的两条技术主线各有岗位名称和产品场景搜索计划；公开匿名版不附带真实目标公司清单，使用者可在本地补充公开可核验的公司产品线索。
5. **按产出调整搜索。** 每 8 次主线搜索，对比去重后符合条件的有效岗位。证据充分时，下一轮从 50/50 调到 60/40；否则保持均衡，两种方法都保留。

这次不修改旧分享版的手机连接、投递脚本或消息权限。找岗结果仍只是本地待复核清单，真实投递按目标电脑现有规则另行确认。

## 安装

1. 在另一台电脑上停止正在运行的项目脚本，并关闭正在使用该项目的 Codex 任务。
2. 将 ZIP 解压到项目目录**之外**，不要直接把整个 ZIP 解压覆盖旧项目。
3. 在解压目录打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Apply-Update.ps1 -TargetDir 'D:\CodexJobAgent-Share-20260915'
```

若那台电脑的项目路径不同，把 `-TargetDir` 改成实际路径。安装器先校验 SHA-256 和目标基线；修改过的程序文件会让它停止。请先比较差异，确实要覆盖时再加 `-AllowModifiedCode`。每个被替换的程序文件都会备份到目标项目的 `.update-backups/`。

安装器**不会覆盖**已存在的 `.local/candidates/` 私人资料，也不会覆盖候选人的运行数据、数据库、日志、简历、登录状态或手机配置。公开匿名版不附带任何真实候选人资料；本地已有资料不会被安装器覆盖。

如果收到的是不含私人资料的 `Core` 包，且目标电脑已有某人的已确认单人 `.local` 资料，可用下面的命令迁移。其他候选人的资料若保存在别处，把 `--source-dir` 指向对应目录；脚本会检查用户确认状态以及可选的候选人 ID。

```powershell
python scripts\migrate_local_candidate.py --candidate candidate_a --source-dir .local
python scripts\migrate_local_candidate.py --candidate candidate_b --source-dir 'D:\另一份已确认资料目录'
```

## 安装后核验

```powershell
python scripts\run_candidate_pool.py --help
python scripts\build_candidate_a_discovery_plan.py --candidate candidate_a
python -m unittest tests.test_discovery_plan tests.test_source_quality
```

生成 Candidate A 搜索计划要求 Candidate A 的本地资料已存在。若缺失，先核对 `.local/candidates/candidate_a/`。`candidate_b` 资料需要在 `.local/candidates/candidate_b/`。候选人的路径定义在 `config/portable_candidate_registry.yaml`。

## 找岗命令

原始公开 JD 放进各自目录，且**每条记录都必须带** `"candidate": "candidate_a"` 或 `"candidate": "candidate_b"`。运行：

```powershell
python scripts\run_candidate_pool.py --candidate candidate_a
python scripts\run_candidate_pool.py --candidate candidate_b
```

输入路径分别为 `data/runtime/candidate_a/discovered_jobs/raw_source_jobs.json` 与 `data/runtime/candidate_b/discovered_jobs/raw_source_jobs.json`。不同候选人的匹配结果、待复核清单和数据库写在各自的 `data/runtime/<candidate>/`，报告写在 `reports/runtime/<candidate>/`。旧的单人数据不会自动混入。

Candidate A 的产品场景计划运行：

```powershell
python scripts\build_candidate_a_discovery_plan.py --candidate candidate_a
python scripts\candidate_a_company_prospects.py --candidate candidate_a --input examples/discovery_strategy/company_prospects.synthetic.json
python scripts\candidate_a_discovery_feedback.py --candidate candidate_a --matches data/runtime/candidate_a/discovered_jobs/matched_jobs.json
```

公开匿名版只提供 `examples/discovery_strategy/` 下的 synthetic 格式示例，不包含真实目标公司或历史搜索记录。真实使用时把公开可核验的公司产品线索写入本地 `data/runtime/<candidate>/discovery_strategy/`，并在目标招聘平台核对当前具体在招岗位和完整 JD。

## 包含与排除

本包仅包含更新程序、通用化策略、测试和 synthetic 产品线索格式示例。**不包含**旧电脑或当前电脑的岗位数据库、投递记录、审计日志、手机配置、Cookie、密码、验证码、虚拟环境、下载依赖和简历 PDF。

公开匿名版不包含 `.local/candidates/`。真实姓名、联系方式、简历与本地求职记录应始终保留在公开仓库之外。
